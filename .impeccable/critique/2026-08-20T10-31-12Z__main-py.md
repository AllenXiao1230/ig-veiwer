## Design Specificity Verdict

The workflow is specifically authored for offline Instagram export analysis: local JSON import, relationship metrics, sensitive-export warnings, local snapshots, and profile handoff are cohesive. Its visual presentation is still category-interchangeable: the fixed dark QSS palette, generic five-metric strip, and dense dashboard command bar could be used by a CRM or file manager. The product's strongest distinction - private, offline analysis - is absent from the primary first-run surface.

## Overall Impression

This is a safe, capable analysis tool whose implementation trustworthiness is ahead of its first-use experience. The single biggest opportunity is to turn a dense all-at-once dashboard into a guided local-analysis workflow that makes its privacy promise visible before users import social-relationship data.

## What's Working

1. Safety appears at the decision points: cache clearing, sensitive CSV export, and multi-page opening use confirmations, and batch opening is throttled.
2. The analytical route is coherent: import, inspect relationship metrics, select a list, search/sort accounts, then optionally preview a profile.
3. Background import reporting, malformed-source summaries, snapshot feedback, and browser-load feedback avoid silent failures.

## Priority Issues

### [P1] Flattened and non-adaptive command hierarchy

The top action row exposes two imports, five utilities, and batch-opening controls before the user has data (`main.py:165-250`). Fixed/minimum sizes in the toolbar, dashboard, table and preview panels compound the issue at narrower desktop widths or enlarged system text (`main.py:211`, `228`, `255`, `282`, `302`). Make folder import the single first-run CTA, defer inapplicable actions, move batch opening to a contextual selection bar, and add a narrow-window layout. Suggested command: `$impeccable distill`, then `$impeccable adapt`.

### [P1] No durable first-run or empty-result state

With no imported data, sidebar and table areas are empty and status messages fade; a zero-result filter simply clears the table (`main.py:469-478`, `501-503`). Add a central empty state that explains local JSON import, gives one recommended action, carries the no-login/no-API privacy reassurance, and differentiates "nothing imported" from "no matching accounts." Suggested command: `$impeccable onboard`.

### [P1] Ambiguous, irreversible batch opening

`_selected_or_visible_items` silently switches between selected rows and all visible rows (`main.py:603-604`); after confirmation, `_open_next_profile` keeps opening external tabs without a Stop control (`main.py:610-641`). Make the scope explicit, disable the action without an intentional scope, expose queued/completed counts, and add Cancel. Suggested command: `$impeccable clarify` and `$impeccable harden`.

### [P1] Accessibility and keyboard gaps

The source declares no accessible names/descriptions, label buddies, tab order, or shortcuts. The preview controls are glyph-only (`main.py:308-319`). White text on the green primary button is approximately 3.37:1, below the 4.5:1 normal-text contrast threshold (`main.py:76-80`). Add accessible names, label associations, a visible focus treatment, standard shortcuts, and a higher-contrast green or darker text treatment. Suggested command: `$impeccable harden`.

### [P1] Main-thread table work will not scale predictably

Every search input filters all records and recreates every `QTreeWidgetItem` (`main.py:227`, `501-533`); sorting repeats the same path (`main.py:586-601`). Cache loading also builds insights and renders synchronously on startup (`main.py:469-478`). Debounce search, use a model/proxy approach rather than rebuilding rows, and background large-cache loading. Suggested command: `$impeccable optimize`.

## Persona Red Flags

### Alex - power user

- No keyboard accelerators for import, search, export, preview navigation, or reset.
- Batch opening offers arbitrary counts rather than a deliberate selected-versus-filtered scope.
- Copy is only discoverable in a context menu; no fast bulk-copy path is visible.

### Jordan - first-timer

- The app does not explain the recommended import path in the empty canvas.
- "匯入資料夾" and "匯入檔案" impose a file-structure choice before explaining the difference.
- `CSV`, `摘要`, `紀錄`, `趨勢`, and `清快取` have short labels and depend on hover help.

### Sam - accessibility-dependent user

- Icon-only preview controls have no programmatic accessible names in the source.
- Focus behavior, VoiceOver wording, and large-text behavior have no intentional implementation evidence.
- The low-contrast green action button can be hard to read; metric text is not color-only, which is a positive safeguard.

## Minor Observations

- The date filter is a good progressive disclosure pattern but does not explain inverted ranges or no-result outcomes.
- Background failures include a traceback and CSV export shows raw OS exceptions; both should offer a concise recovery path.
- The embedded Instagram preview can cross a privacy boundary unexpectedly on row selection; disclose the external navigation/login implication before the first preview.
- Theme values are raw QSS literals, and the QWebEngine placeholder/chart colors are separately hard-coded, making high-contrast or system theme support difficult.

## Questions to Consider

1. Should the primary experience optimize for a single relationship question, or remain a broad record viewer?
2. Should profile previews be explicit opt-in rather than triggered by selecting a row?
3. Is the offline/private promise central enough to lead the first-run screen?
